# Phase 5 学习指南：地面站通信接口

## A. 这个模块解决什么工程问题

调参和观测如果直接绑在串口中断、全局变量或控制函数上，会形成难以测试的远程控制入口。
本模块把传输帧、请求语义和真实业务动作分开，为未来串口调参和 Linux 地面站提供稳定边界。

## B. 设计思想

- 地面站协议与现有主从 MCU 协议分离；
- 帧层只负责 magic、版本、长度、小端序和 CRC；
- 服务层校验 payload 后再调用依赖注入的业务回调；
- 状态读取使用快照，参数通过稳定 ID 和原始类型值传输；
- 控制命令不直接操作电机，解锁必须由应用安全守卫决定；
- sequence 关联请求响应，错误使用统一结构返回；
- codec 无动态内存、无阻塞 IO、可在主机独立测试。

## C. 涉及嵌入式知识

- 二进制协议 framing、字节序和 CRC；
- UART DMA/中断环形缓冲；
- ISR 与任务上下文分工；
- 数据一致性快照；
- 命令分发和依赖反转；
- 协议版本与向后兼容；
- 远程控制的认证、授权和重放防护；
- 模糊测试、错误注入和超时恢复。

## D. 面试如何描述

> 我为飞控设计了独立的地面站 Version 1 协议，采用长度字段、sequence 和
> CRC16-CCITT。编解码层与业务层分离，业务通过回调读取状态和参数、提交控制请求。
> 协议层不会直接解锁或驱动电机，未知命令在回调前拒绝，应用仍负责 armed、故障和
> 油门等安全守卫。实现无动态内存，并用主机测试覆盖编解码、CRC、参数和命令拒绝路径。

## E. 后续我需要自己学习什么

1. UART idle-line + DMA 环形接收；
2. 增量流解析和粘包/丢字节恢复；
3. TX 队列背压与带宽预算；
4. HIL 协议测试和字节流 fuzz；
5. challenge-response、消息认证码和防重放；
6. Linux 串口库、协议状态机和参数缓存；
7. 协议 schema 生成与 Wireshark dissector。
